herdr 操作チュートリアル

API サーバーに機能を 1 つ足す作業を、エージェント 2 体（実装役とレビュー役）に任せる、という筋書きで進みます。上から順に操作すると、herdr でできることを一通り通ります。

画面の図は説明のための模式図で、実際の見た目とは違います。ペイン ID（w1:p1 など）は例です。実際の値は herdr pane list や herdr agent list で確かめてください。

全体の流れ

  1. インストールと起動セッション / 名前付きセッション
  2. 画面を組むWorkspace・Tab・Pane、マウス、prefix キー
  3. エージェントを起動自動検出、integration
  4. 状態を見張るサイドバー、上の階層への伝搬、名前付け
  5. タスクを worktree に分けるworktree で Workspace を作る
  6. CLI で連携させるpane run / wait-output、agent prompt / wait
  7. エージェントに自分で操作させるエージェント用のスキル
  8. Socket API で状態を受け取るNDJSON、イベント購読
  9. 離席と再接続detach / attach、agent attach
  10. リモートの開発機で動かす--remote、machine、--machine
  11. 再起動と更新レイアウトの復元、会話の resume、handoff
  12. 調子が悪いときagent explain、検出ルールの上書き
  13. 広げる・片付ける設定、プラグイン、終了

STEP 1
インストールと起動

curl -fsSL https://herdr.dev/install.sh | sh   # または brew install herdr / mise use -g herdr
herdr --version

cd ~/work/api
herdr                                          # デフォルトのセッションを起動して attach

herdr を実行すると、裏でサーバーが立ち上がり、いま開いているターミナルがそのクライアントになります。ターミナルアプリを替える必要はありません。

用途ごとに完全に分けたいときは、名前付きのセッションを使います。

herdr --session demo        # 別のサーバー名前空間。デフォルトのセッションとは干渉しない
herdr session list
確認herdr status でサーバーとクライアントの状態を見られます。ペインの中にいると環境変数 HERDR_ENV=1 が立ちます。herdr の中でもう一度 herdr を起動すること（入れ子）はできません。

STEP 2
画面を組む

実装役、レビュー役、開発サーバーの 3 つのペインを作ります。マウスだけでも操作できます。

やることマウスキー（prefix = ctrl+b）
右に分割右クリックメニューprefix → v
下に分割右クリックメニューprefix → -
フォーカスを移すペインをクリックnavigate モード
サイズを変える境界をドラッグ—
新しいタブ—prefix → c
コピードラッグで選択—
キー一覧—prefix → ?

手順: prefix v で右に分割し、右のペインで prefix - を押して下に分割します。右下のペインで開発サーバーを起動します。

npm run dev      # 右下のペイン w1:p3

STEP 3
エージェントを起動する

左のペインで Claude Code を、右上のペインで Codex を、いつも通り起動します。herdr はエージェントをラップしません。ペインのプロセスと画面を見て、自動で検出します。

claude          # w1:p1
codex           # w1:p2

検出の精度を上げるために、エージェントごとの integration を入れます。入れるとエージェントが状態を直接報告するので、画面から推測するより正確になります。サーバーを再起動したあとに会話を再開する機能（STEP 11）にも必要です。

herdr integration install claude
herdr integration install codex
herdr integration status          # 入っているか、古くないか
確認herdr agent list に claude と codex が出ていれば検出できています。

STEP 4
状態を見張る

claude に作業を頼んだら、あとはサイドバーを見るだけです。ペインを順に覗いて回る必要はありません。

エージェントに役割の名前を付けておくと、以降の CLI で名前を使って指定できます。

herdr agent rename w1:p1 impl
herdr agent rename w1:p2 codex
herdr agent list

blocked になったら、そのペインをクリックして承認するなり答えるなりします。

STEP 5
タスクを worktree に分ける

レビューを同じ作業ツリーでやらせると、実装中の変更とぶつかります。Git worktree を作り、それを専用の Workspace として開きます。

herdr worktree create --cwd ~/work/api --branch feature-x
herdr worktree list
herdr workspace list            # 新しい Workspace（例: w2）が増えている

STEP 6
CLI で連携させる

ここからは、普通のシェルや別のペインから herdr コマンドで操作します。ほとんどのコマンドは JSON を返すので、そのままスクリプトに組み込めます。

6-1. 開発サーバーの起動を待つ

herdr pane run w1:p3 "npm run dev"                               # 入力して Enter
herdr pane wait-output w1:p3 --match "ready" --timeout 60000    # 出力に一致するまで待つ
herdr pane read w1:p3 --source recent --lines 30                 # ログを読む

6-2. レビュー役を起動して、実装役と連携させる

# w2 に空のシェルのペインがある前提。新しく作るなら pane split
herdr pane split w2:p1 --direction right --cwd ~/work/api-feature-x
herdr agent start reviewer --kind claude --pane w2:p1

# 実装役に頼み、終わるまで待つ
herdr agent prompt impl "/users に検索 API を追加して、テストも書いて" --wait --timeout 900000

# レビュー役に渡し、終わるまで待つ
herdr agent prompt reviewer "main との差分をレビューして、問題を箇条書きで" --wait
herdr agent read reviewer --lines 80

# 指摘を実装役に戻す。承認待ちになったら止める
herdr agent prompt impl "レビューの指摘を直して"
herdr agent wait impl --until blocked --timeout 600000
注意状態は画面から判定していることがあります。判定ルールが合わないと、blocked のはずが idle に見えることがあり、そのまま自動で入力すると承認ダイアログにキーを打ち込んでしまいます。自動化するエージェントには integration を入れ、怪しいときは STEP 12 の agent explain で確かめてください。

STEP 7
エージェントに自分で操作させる

STEP 6 の操作を、エージェント自身にさせることもできます。herdr の操作方法を教えるスキルを入れます。

npx skills add herdrdev/herdr --skill herdr -g

入れたあと、impl にこう頼みます。

> 右にペインを分けてレビュー用の claude を起動し、いまの変更をレビューさせて。
  終わったら指摘を読んで直して。

impl は herdr pane split、agent start、agent prompt --wait を自分で実行し、サイドバーにレビュー役が増えます。

STEP 8
Socket API で状態を受け取る

自作のツール（通知や集計のダッシュボードなど）からつなぐときは、ソケットを直接使います。1 行に 1 つの JSON を送ります（NDJSON）。

# ソケットの場所: ~/.config/herdr/herdr.sock（名前付きセッションは sessions/<name>/herdr.sock）
echo '{"id":"1","method":"pane.read","params":{"pane_id":"w1:p3"}}' \
  | nc -U ~/.config/herdr/herdr.sock

# 返ってくる形
# {"id":"1","result":{...}}  /  {"id":"1","error":{"code":"not_found","message":"..."}}

herdr api schema --json      # メソッドとイベントの完全なスキーマ
  • events.subscribe を送ると接続がつながったままになり、エージェントの状態の変化やペインの出力の一致などのイベントが流れてきます。購読のフィルタの書き方はスキーマで確かめてください。
  • 過去のイベントは再送されません。events_lost が来たら、購読し直して session.snapshot を取り直します。イベントは「状態を読み直す合図」として扱います。
  • たいていの用途は STEP 6 の CLI で足ります。

STEP 9
離席と再接続

エージェントが作業している間に、席を外します。

prefix q          # detach。ターミナルのウィンドウを閉じても同じ
# …ノートPCのスリープ、SSH の切断があっても動き続ける…
herdr             # 再 attach。レイアウトも画面もそのまま

herdr の画面全体ではなく、エージェント 1 つにだけつなぐこともできます。

herdr agent attach reviewer              # そのエージェントのターミナルだけを表示
herdr agent attach reviewer --takeover   # 別のクライアントが入力を握っているときに奪う

STEP 10
リモートの開発機で動かす

長い作業は、常時動いている開発機に任せます。SSH の設定に workbox という別名がある前提です。

# 1 回だけ: SSH の先で herdr を起動する（開発機にもインストールが必要）
herdr --remote workbox                       # 手元は薄いクライアント。キー設定は手元のものを使う

# 開発機を登録すると、手元と並べて 1 画面で見られる
herdr machine add workbox --label "Build machine"
herdr machine list
herdr machine status

# CLI を開発機へ転送する
herdr --machine "Build machine" agent list
herdr --machine "Build machine" worktree create --cwd /srv/api --branch review
herdr machine reconnect "Build machine"      # 切れたら SSH の認証からやり直す

--machine は --session や --remote と同時には使えません。インストール、セッションの管理、対話的な attach は転送されません。

STEP 11
再起動と更新

サーバーを止めて、もう一度起動します。

herdr server stop
herdr             # レイアウトが戻る。integration を入れたエージェントは会話を再開する
場面プロセスレイアウトと cwd直近の画面エージェントの会話
detach → 再 attach（STEP 9）残る残る残る残る
サーバーの再起動消える（新しいシェルになる）残るpane_history を有効にしたときだけnative resume（デフォルトで有効）
herdr update --handoff引き継ぎに成功すれば残る残る成功すれば残る成功すれば残る
# ~/.config/herdr/config.toml
[experimental]
pane_history = true              # 再起動後に画面の履歴を再生する。秘密情報が残りうるのでデフォルトは無効

[session]
resume_agents_on_restore = true  # 会話の再開（デフォルトで有効）

herdr を更新するときは、動いているペインを引き継ぐ handoff（実験的）が使えます。

herdr update --handoff    # 公式のインストールスクリプトで入れた場合だけ。brew / mise / nix では使えない
注意サーバーを再起動すると、開発サーバーやテストのプロセスは止まります。STEP 6-1 の pane run でもう一度起動してください。

STEP 12
調子が悪いとき

症状やること
エージェントが一覧に出ない・状態がおかしいherdr agent explain impl --json で判定の理由を見る。herdr integration status も見る
サンドボックスや VM の中で動かしていて検出されない環境変数 HERDR_AGENT でエージェントの種類を指定する
判定ルールを自分で直したい~/.config/herdr/agent-detection/<agent>.toml に書くと、配布されたルールより優先される。herdr server reload-agent-manifests で反映
キーを押しても反応しないOS やターミナルがそのキーを先に取っている。[keys] で割り当てを変える
起動できない・ソケットのエラーherdr status server / herdr status client。ログは ~/.config/herdr/

STEP 13
広げる・片付ける

設定とプラグイン

herdr --default-config > ~/.config/herdr/config.toml   # デフォルト値を書き出して編集する
herdr server reload-config                             # ペインを止めずに反映

キー、テーマ、サイドバー、通知、スクロールバックを変えられます。tmux の中で herdr を使うなら、prefix がどちらも ctrl+b なので、どちらかを変えてください。プラグイン（ファイルビューア、レビュー用のサイドバー、Telegram への通知など）は herdr.dev/plugins にあります。

片付ける

herdr worktree list
herdr worktree remove …          # 引数は herdr worktree remove --help で確認
herdr workspace close w2
herdr session stop demo          # STEP 1 で作った名前付きセッション
herdr server stop                # デフォルトのセッションを止める
